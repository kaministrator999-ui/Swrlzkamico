# Server 2.3.151 / Web Chat 1.5.26 — Edge Android native fixed IME boundary

## Problem

Microsoft Edge for Android continued to show a black shelf between the Chat interface and Edge's bottom browser/keyboard boundary while the composer was focused. Chrome remained correct. The earlier visual-viewport compensation did not remove the shelf.

## Root cause

Edge can expose an undersized `visualViewport.height` during IME focus while its native fixed-position viewport extends farther downward. The Android Chat shell forced `.app` to the JavaScript-computed height, so the shell stopped early and exposed the body background beneath it.

## Correction

- The live hot asset `web/chat_enhancements.css` now owns an Edge-Android-only IME override.
- While `swrlz-edge-android` and `swrlz-ime-open` are active, `.app` keeps its current top boundary but switches from an explicit computed height to `bottom: 0; height: auto`, delegating the lower edge to Edge's native fixed-position containing block.
- `.workspace` continues to fill the corrected app height so the composer follows the browser-owned lower boundary.
- The sidebar and scrim receive the same native lower-boundary rule for consistency if opened while the IME is active.
- Chrome and other Android browsers remain on the existing visualViewport path unchanged.

## Lineage cleanup

The debugging sequence produced several preparation-only commits and one server-version-only commit. None of those changed the live Chat CSS path. This correction removes the temporary/unwired artifacts from the current tree while preserving their Git history and applies the fix through the already hot-synced `chat_enhancements.css` asset.
