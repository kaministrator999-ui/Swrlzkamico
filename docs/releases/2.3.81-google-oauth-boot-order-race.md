# Server Runtime 2.3.81 — Google OAuth boot-order race repair

## Release
- Server Runtime: 2.3.81
- Web Chat: 1.4.73
- Google Account Architecture: 1.0.8
- Source branch: `runtime`
- Deployment class: runtime-hot; Vercel may create a preview deployment from the runtime commit, but no stable production backend redeploy is required for this repair.

## Problem
`chat_enhancements.js` registers the Chat account-footer boot before `chat_google_server_config.js`. Both wait for `DOMContentLoaded`, so the account footer can read and initialize Google Identity Services with a retired browser-stored OAuth client ID before the later Google bridge repairs local storage. This preserves the visible Google 401 / blocked-origin failure even after the server and browser recovery logic are otherwise correct.

## Repair
`web/chat_google_server_config.js` now repairs browser OAuth state synchronously as soon as the bridge script is parsed. Empty browser state and the specifically retired client ID are replaced with the canonical Web OAuth client before `DOMContentLoaded` fires. Any other non-retired browser-proven client ID remains preserved.

The asynchronous server-status reconciliation remains in place and server-side Google ID-token verification remains authoritative.
