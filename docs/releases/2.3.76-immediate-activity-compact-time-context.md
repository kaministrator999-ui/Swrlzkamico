# Server Runtime 2.3.76 — Immediate Activity + Compact Social/Temporal Context

**Server Runtime:** 2.3.76  
**Web Chat:** 1.4.69  
**LALM Engine:** 2.1.30 (`2.1.30-hot-compact-social-temporal-v20`)  
**User Time Context:** 1.0.1  
**Deployment:** none  
**Restart:** none

## Triggering evidence

A fresh first-turn `Hey` showed three problems together: Chat remained on `Connecting to §wyrlz` before the server emitted activity, the first-turn prompt prefetched 537 tokens and was classified `kind=normal`, and the Edge sidebar correctly surfaced that Google account auth is not configured on the server.

## Changes

- Added `web/chat_activity_immediate.js` so a request gets a local `ANALYZING_REQUEST` receipt immediately when the stream request leaves Chat, before the first server event arrives.
- Changed user-local time transport from prompt/history prefix markers to structured `swrlzUserTimeContext` metadata. Raw user wording is preserved for intent/social classification and prefix reuse.
- LALM 2.1.30 consumes structured user-local time at the engine boundary and uses a compact engine conversation contract.
- For a simple greeting, the engine does not append the larger client cognitive directive; this keeps the social opening lightweight and prevents RMCCA/time plumbing from turning `Hey` into a large `kind=normal` first-turn prompt.
- The social contract still forbids service-desk closings on an opening greeting and retains identity disambiguation.
- Runtime manifest advanced to v10 to load immediate activity and the lean time-context transport.

## Concurrency/version guard

Entry authorities were Server 2.3.75 / Web Chat 1.4.68 / LALM 2.1.29 / User Time Context 1.0.0. They were re-read immediately before version assignment and were unchanged, so the event advanced to 2.3.76 / 1.4.69 / 2.1.30 / 1.0.1 without a version collision.

## Google account state

The browser-side cross-browser configuration bridge is functioning as designed: Edge now reports the authoritative server state instead of depending on Chrome-local test configuration. Production account status still lacks the stable server-side Google/session/store configuration. That remaining auth configuration belongs to the deployment/stable infrastructure boundary and was not changed by this runtime release.

## Acceptance gates

- Fresh `Hey` should show Activity Log immediately rather than sitting only on `Connecting to §wyrlz`.
- Engine planning should classify raw `Hey` as brief-social rather than normal.
- First-turn prefill should be materially lower than the 537-token regression.
- The model should greet naturally without a support-style conversation closer.
- User-local time remains available to the model through structured metadata without appearing in visible prompt text.
