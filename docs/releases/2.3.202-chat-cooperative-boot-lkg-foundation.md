# Server 2.3.202 — cooperative Chat boot + LKG foundation

## Versions
- Server Runtime: **2.3.202**
- Web Chat: **1.5.54**

## Live evidence
The inline pre-runtime probe proved the base Chat script executes and `.app` exists on the affected Android Chrome client. The probe reached `base-chat-script-complete`, but did not reach DOMContentLoaded/window-load telemetry during the observed failing runs. This localizes the hang after the base script and inside/around runtime augmentation rather than HTML construction.

## Regression identified
The recorded 2.3.145 / Chat 1.5.22 mobile-freeze correction explicitly required a 1.6 second functional settling window, a browser yield between every functional helper, and decorative hydration only after the functional layer settles. The current loader had lost those cooperative scheduling guarantees and started wallpaper/decorative work concurrently with critical/functional boot.

## Repair
- Restore cooperative browser yields between critical and functional helpers.
- Restore the 1.6 second settling window before the functional graph.
- Move wallpaper and Ice Dragon art settlement behind functional readiness.
- Keep the inline pre-runtime logger as an independent telemetry path.
- Introduce `swrlz.chat.lkg.v1` candidate/verified runtime state. A candidate is promoted only after the full functional asset chain completes.
- On watchdog/fatal failure, explicitly mark runtime mode `emergency-base`; a broken candidate is never promoted.

## LKG limitation / next step
This change establishes truthful promotion state but does not fabricate a historical LKG asset bundle. Existing records contain an acceptance target for 2.3.145 / Chat 1.5.22, but not sufficient live verification evidence to declare that historical revision the current LKG automatically. Once a candidate completes functional boot on a real client, its revision becomes the browser's LKG authority. A future immutable server-side LKG bundle can use the same state machine for cross-device recovery.

## Deployment
Runtime-only change. No Vercel deployment or restart requested/performed.
