# Server 2.3.200 — Chat boot visibility + live stage observability

## Versions
- Server Runtime: **2.3.200**
- Web Chat: **1.5.53**

## Evidence
A real Android Chrome load rendered the Ice Dragon wallpaper but no foreground Chat shell. This proved the runtime/theme path was executing while the `.app` foreground remained hidden.

Inspection found a second visibility gate in `web/chat_boot_guard.css`: `html.swrlz-visual-booting body .app` forced `opacity:0`, `visibility:hidden`, and disabled pointer events until the entire functional/decorative boot completed. That contradicted the fail-open first-paint repair.

## Changes
1. `chat_boot_guard.css` now keeps the structural `.app` visible and interactive during visual boot. Decorative readiness is no longer allowed to hide Chat.
2. `chat_runtime_loader_v3.js` now publishes `data-swrlz-boot-stage`, records each asset stage to the live debug logger, records script/style errors and timeouts with stage context, captures shell geometry/computed visibility, and has a 12-second fail-open watchdog.
3. `chat_debug_log_v1.js` v9 now sends the current boot stage with live events and records `.app`, workspace, topbar, messages, composer, sidebar geometry plus display/visibility/opacity/pointer-events at DOM-ready, state changes, +2s, +6s, and +12s.

## Expected diagnostic result
If Chat still hangs, `/api/chat/client-debug` receives enough stage and computed-layout evidence to identify the exact script/asset/stage at which progress stopped rather than inferring from a screenshot.

## Deployment
Runtime-only hotfix. **No Vercel deployment or restart requested/performed.**
