# Server Runtime 2.3.73 — LALM social participation + Google server-config bridge

Date: 2026-09-12
Branch: `runtime`

## Versions
- Server Runtime: 2.3.73
- Web Chat: 1.4.67
- LALM Engine: 2.1.27 (`2.1.27-hot-social-participation-v18`)
- Google Account Architecture: 1.0.5

## LALM change
The proven 2.1.26/v17 inference and token-exact checkpoint implementation is preserved as `runtime_hot/r39_engine_v17_base.py`. The active `r39_engine.py` becomes a small v18 wrapper that installs an engine-owned conversation contract before prompt rendering.

The contract explicitly requires social participation rather than meta-description for greetings, distinguishes the user's preferred name from the assistant identity, and gives concrete greeting/identity examples. Browser RMCCA guidance is retained as a secondary policy rather than being the sole source of this behavior.

Expected regression targets:
- `Hey 👋` -> direct natural greeting, not `This is a friendly greeting...`
- `You can call me Kami 😜` -> acknowledge Kami as the user's preferred name
- `What's your name?` -> natural first-person answer identifying §wyrlz

## Google account change
A new runtime Chat bridge requests `/api/account/status` and obtains `googleClientId` from the server authority. When present, it mirrors that public client ID into the legacy browser-local compatibility key and reloads once, allowing a fresh browser to initialize the existing Google Identity UI without visiting the isolated test page first.

If the server reports no client ID, Chat now reports that Google sign-in is not configured on the server rather than incorrectly presenting the problem as device-specific.

## Stable-boundary note
The current production account endpoint reported `authConfigured=false`, `storeConfigured=false`, and `googleClientId=null` before this runtime event. This release fixes the browser/config authority path but does not invent or expose OAuth credentials. Full Google sign-in still requires the production stable environment to provide `SWRLZ_GOOGLE_CLIENT_ID` and a valid `SWRLZ_SESSION_SECRET`, plus the configured durable store for account-backed state. Changing those stable environment values can require a deployment and therefore remains behind the explicit deployment approval gate.

## Deployment
No Vercel deployment is requested by this runtime release.
