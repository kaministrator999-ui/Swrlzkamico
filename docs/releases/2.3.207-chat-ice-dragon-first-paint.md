# Server 2.3.207 / Chat 1.5.57 — Ice Dragon first-paint correction

## Evidence
Android screenshots after restoring the canonical Chat shell showed that the base/default visual shell could paint first, then Ice Dragon styling and wallpaper arrived later. Client logs consistently showed `theme-init saved=ice-dragon` followed by theme application, while wallpaper asset settlement occurred seconds later.

## Root cause
The cooperative runtime loader established theme state during hydration, but the canonical wallpaper script was deliberately deferred until after the entire functional graph. Android viewport authority was also established by the runtime loader rather than the first-paint helper. This allowed a visually valid but stale/default shell to be shown before the intended Ice Dragon state.

## Change
`web/chat_early_shell_ready_v1.js` advances its internal contract to v2 while retaining the stable manifest path. It now:
- establishes the saved/default Ice Dragon theme before runtime hydration,
- establishes Android device and visual-viewport geometry before runtime hydration,
- paints the canonical Ice Dragon workspace wallpaper immediately using the same asset authority as the later wallpaper owner,
- provides the minimum Android workspace geometry needed for the intended edge/gutter state,
- leaves functional/decorative hydration ownership with `chat_runtime_loader_v3.js`.

`runtime_pages/manifest.json` advances from generation 118 to 119 so the changed early-shell asset receives a fresh immutable URL generation instead of reusing a cached v118 asset.

- Server Runtime: 2.3.207
- Web Chat: 1.5.57
- Runtime manifest: 119

## Deployment state
Runtime-only hot update. No Vercel deployment or server restart performed.
