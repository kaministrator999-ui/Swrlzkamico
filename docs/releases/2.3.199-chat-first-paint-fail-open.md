# Server 2.3.199 — Chat first-paint fail-open repair

## Versions

- Server Runtime: **2.3.199**
- Web Chat: **1.5.52**

## Reported failure

The Chat page was reported as not loading.

## Evidence before change

- Production `/chat` returned HTTP 200 from `github-runtime`, `runtime` branch, `web/chat.html`, manifest revision 117.
- Recent `/api/chat` and runtime asset requests returned HTTP 200 and no production 4xx/5xx cluster was present.
- The first-paint guard still hid the complete `.app` until `.swrlz-main-chat-ready` appeared.
- The early-shell readiness script is loaded after the full base document script, so any browser-side parse/execution/load interruption before that point can leave an otherwise usable Chat shell permanently invisible.

## Change

Changed only `web/chat_first_paint_guard.css` so the complete base Chat shell fails open: `.app`, noise, and ambient layers remain visible and interactive even before runtime enhancement readiness. Readiness classes remain observable, but no longer control whether the user can see Chat.

Dialog and toast visibility remain governed by their native/component behavior.

## Architecture

Runtime-only hotfix. No stable loader, API, middleware, authentication, deployment configuration, or bundled dependency changed.

## Deployment

**No Vercel deployment requested or performed.** The runtime loader is expected to serve the current `runtime` source directly.

## Verification target

1. Live `/chat` remains sourced from GitHub `runtime`.
2. Live first-paint guard contains the fail-open rule.
3. Chat shell remains visible even if enhancement readiness is delayed or fails.
4. Server and Chat authorities report 2.3.199 and 1.5.52.
