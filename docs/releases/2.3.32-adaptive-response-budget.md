# Server v2.3.32 — Adaptive response budget

Date: 2026-09-11

## Module state

- Server runtime: **v2.3.32**
- LALM engine: **v2.1.22** (`2.1.22-hot-boundary-v13-adaptive-response-budget`)
- Web Chat: **v1.4.27** unchanged
- LALM UI: **v1.0.0** unchanged

## What changed

The local R39 generator no longer defaults every request to a fixed 128-token response leash. The LALM now plans an output budget from the current request type and complexity. Each request receives a planned response size, a soft wrap point, and a larger emergency ceiling.

Coding requests receive a larger default plan than ordinary conversation, and multi-file/project-style coding requests receive additional room. Short social turns retain a small plan so the change does not encourage needless verbosity.

The budget is advisory rather than a target: the prompt explicitly tells the LALM to converge near the soft wrap point, not to pad to the planned size, and to continue beyond the plan when needed to finish code blocks, syntax, sentences, lists, or sections it already started.

The decode loop emits response-budget telemetry when the plan is established and when the soft wrap point is reached. If generation reaches its current emergency ceiling while an obvious code fence/bracket/brace/parenthesis structure is still open, the runtime grants bounded completion headroom in 64-token steps, up to an absolute 768-token safety ceiling.

Manual generation limits remain possible only when a caller explicitly selects `budgetMode=manual`; a legacy/default `maxTokens=128` value no longer silently forces every normal request to stop at 128.

## Interaction with prefill/checkpoints

The v2.1.21 pipelined-prefill architecture is preserved. The budget advisory is inserted into the canonical prompt before prefill so hidden mid-decode control tokens are not injected into recurrent/KV state. This keeps exact-prefix checkpoint reuse valid while still giving the model advance knowledge of when it should begin wrapping up.

Longer complete assistant answers can therefore become valid reusable conversation checkpoints instead of leaving the next turn with an assistant response truncated at the old fixed boundary.

## Failure / motivating evidence

A captured C++ response reached decode step 128 and immediately completed while the prose ended mid-sentence (`Includes: Required libraries (iostream) are`). That demonstrated that the prior fixed limit, rather than natural completion, was terminating otherwise valid responses.
