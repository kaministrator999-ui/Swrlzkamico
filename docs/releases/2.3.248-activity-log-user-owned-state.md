# Server 2.3.248 — Activity Log user-owned state

## Status

Runtime-hot source complete. Chat 1.5.74. No Vercel deployment requested or performed.

## Symptom

The Activity Log could rapidly open and close after a response completed. Earlier repairs preserved `message.meta.activityExpanded`, but the visible control still mixed native `<details>/<summary>` behavior, open-attribute observation, terminal DOM replacement, and historical incremental-stream writes.

## Architecture reconciliation

The Activity Log expansion state has one canonical owner: `message.meta.activityExpanded`. Its mutation policy is now user-write-only. Streaming events, renderer replacement, observers, completion/finalization, and compatibility code may read the state and render from it but may not change it.

## Change

`web/chat_activity_immediate.js` now renders a controlled Activity panel with a normal button rather than relying on native `<summary>` toggling. The button is the only path that flips `message.meta.activityExpanded`. Native `toggle` listeners and `open`-attribute observation were removed. Historical `details.trace` output from older renderers is hidden from presentation so its legacy `open` writes cannot compete with the canonical panel.

The Activity surface is still created for live assistant turns and retained for completed turns with activity history. Re-rendering only reflects the stored state.
