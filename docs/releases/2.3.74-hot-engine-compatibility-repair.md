# Server Runtime 2.3.74 — hot-engine compatibility repair

Date: 2026-09-12
Branch: `runtime`

## Versions
- Server Runtime: 2.3.74
- Web Chat: 1.4.67 (unchanged from 2.3.73 event)
- LALM Engine: 2.1.28 (`2.1.28-hot-social-participation-v18b-single-file-loader`)
- Google Account Architecture: 1.0.5 (unchanged from 2.3.73 event)

## Why this repair exists
Server Runtime 2.3.73 / LALM 2.1.27 attempted to split the proven v17 engine into an archived sibling plus a small v18 wrapper. Live verification showed the stable hot-loader allowlist hydrates only `r39_engine.py`, so the wrapper could not import `r39_engine_v17_base.py` and the live engine correctly reported `ModuleNotFoundError`.

Per project versioning rules this failed attempt remains a distinct release event; it is not hidden or overwritten.

## Repair
The 2.1.28 wrapper keeps the stable loader's single-file contract. It first uses a local cached v17 archive if present; otherwise it retrieves the immutable archived v17 source from the runtime branch once, validates the required engine entrypoints, caches it beside the hot engine, and loads it. The wrapper then applies the engine-owned social/identity conversation contract.

This preserves the proven v17 inference/checkpoint implementation while still moving greeting/identity behavior into the LALM engine prompt boundary.

## Deployment
No Vercel deployment requested or triggered by this repair.
