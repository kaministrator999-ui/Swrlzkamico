# Server 2.3.149 / Web Chat 1.5.26 — Edge Android native IME boundary repair

## Problem

User acceptance on Microsoft Edge for Android showed that the 2.3.147 / Web Chat 1.5.24 visual-viewport compensation did not remove the black shelf above Edge's bottom browser bar while the keyboard was open. Chrome remained correct.

The failed heuristic remains in lineage. This event changes ownership of the Edge keyboard-time vertical boundary rather than adding another numeric viewport guess.

## Correction

- Added an Edge-Android-only IME override to `web/chat_enhancements.css`.
- While Edge Android has an editable control focused and the keyboard is open, `.app` no longer uses the JavaScript-computed explicit height. It keeps its current top boundary, uses `bottom: 0`, and lets Edge's native fixed-position containing block determine the visible lower boundary.
- The workspace continues to fill the app grid, so the composer follows the browser-owned lower edge instead of stopping at the undersized `visualViewport.height` value that produced the black shelf.
- Chrome and other Android browsers keep the existing visual-viewport path unchanged.
- No server routing, transcript, account, LALM, or stream behavior changes.

## Deployment state

Runtime-hot Chat asset only. No Vercel deployment and no server restart are required or authorized.

## Verification target

On Microsoft Edge for Android, focus the Chat composer and open the keyboard. Verify that the Chat shell extends continuously to Edge's browser/keyboard boundary with no black shelf. Re-check Chrome to confirm its already-correct keyboard geometry is unchanged.
