# Server 2.3.147 / Web Chat 1.5.24 — Edge Android IME viewport repair

## Problem

On Microsoft Edge for Android, opening the software keyboard could leave a black shelf between the bottom of the Chat interface and the browser/keyboard area. Chrome on the same device rendered correctly.

The cause was a browser-specific viewport disagreement: Edge could report a reduced `visualViewport.height` while its layout viewport had already been resized around the IME. Chat used the smaller visual viewport as authoritative height, effectively applying the keyboard reduction twice and making the fixed app surface too short.

## Correction

- Updated `web/chat_runtime_loader_v3.js` viewport synchronization.
- Android Edge is detected separately from generic Android Chromium.
- While an editable control is focused, if Edge reports a visual viewport materially shorter than the already-resized layout viewport, Chat uses the layout viewport height as the effective `--swrlz-vvh` value.
- Chrome and other Android browsers continue using the existing visual viewport path.
- Added diagnostic fields for raw visual height and whether Edge IME compensation is active.
- Chat runtime loader advanced from REV92 to REV93.
- Runtime publication manifest advanced from v92 to v93.

## Verification target

On Android Edge, focus the Chat composer and open the software keyboard. The Chat workspace should extend to the browser's keyboard boundary with no black shelf. Dismiss and reopen the keyboard and verify the composer remains visible. Repeat in Chrome to confirm its previously correct viewport behavior is unchanged.
