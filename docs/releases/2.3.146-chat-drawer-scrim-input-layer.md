# Server 2.3.146 / Web Chat 1.5.23 — drawer scrim input-layer repair

## Problem

On mobile Chat, opening the left drawer could leave the background dimmer/scrim above the drawer's effective input layer. The drawer looked visually open, but the scrim could intercept taps intended for drawer controls.

The immediately preceding manifest v91 experiment constrained the Android scrim geometry to the exposed workspace. User acceptance on the live mobile interface showed that geometry-only correction was insufficient, so that attempt remains part of the failed-event lineage and this event supersedes it.

## Correction

- Added `web/chat_drawer_layer_v1.js` as a critical Chat boot module.
- The module normalizes the existing drawer and scrim into the same `.app` stacking context before Chat is declared main-ready.
- Existing z-index ownership then becomes deterministic: the drawer remains above the scrim, while the scrim continues to dim/catch taps only behind the drawer.
- Existing scrim click behavior, drawer controls, account controls, thread controls, server routing, transcript state, and LALM behavior are unchanged.
- Chat runtime loader advanced from REV91 to REV92.
- Runtime publication manifest advanced from v91 to v92.

## Version authority

- §wyrlz Server Runtime: `2.3.145` → `2.3.146`
- §wyrlz Web Chat: `1.5.22` → `1.5.23`
- Other module versions unchanged.

## Deployment state

Runtime-only hot publication. No Vercel deployment and no server restart are required or authorized by this event.

## Verification target

On a mobile viewport, open the left drawer and verify that New conversation, thread rows, pin/delete controls, account controls, and other drawer inputs accept taps while the exposed workspace remains dimmed and tap-outside still closes the drawer.
