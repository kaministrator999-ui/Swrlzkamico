## Symptom

After the user-owned Activity Log state repair, the completed-response Activity Log could still require multiple taps before collapsing. The state model was correct, but the new controlled panel still carried the historical `.trace` class used by older Chat enhancement code.

## Architecture reconciliation

`message.meta.activityExpanded` remains the sole persisted visibility state and is user-write-only. The Activity controller remains the canonical UI owner. Legacy native `<details>.trace` elements are compatibility-only and hidden.

The visible controlled Activity panel must therefore not identify itself as a legacy `.trace` component. Otherwise older modules may bind native-details behavior to the new control.

## Change

`runtime/web/chat_activity_immediate.js` Activity controller v5:

- removes `.trace`, `.trace-list`, and `.trace-item` classes from the visible controlled Activity panel;
- gives the panel independent Activity-specific classes and styling;
- keeps one delegated click as the only `activityExpanded` write path;
- stops propagation/default behavior on the Activity button;
- adds `touch-action: manipulation` for deterministic mobile tap handling;
- preserves hidden legacy native traces only for compatibility.
