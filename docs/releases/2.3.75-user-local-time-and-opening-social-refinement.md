# Server Runtime 2.3.75 — User-local time and opening social refinement

## Module versions
- Server Runtime: 2.3.75
- Web Chat: 1.4.68
- LALM Engine: 2.1.29 (`2.1.29-hot-social-temporal-v19`)
- User Time Context: 1.0.0
- Google Account Architecture: unchanged at 1.0.5

## User-visible goal
A first-turn greeting should remain an opening rather than immediately sounding like a service wrap-up, and time-sensitive wording should be grounded in the user's browser-local time rather than an unspecified server clock.

## Changes
1. Added `web/chat_user_time_context.js` and loaded it before canonical Chat request preparation.
2. Each user message is supplied to the model with a hidden, stable local-time marker containing local date, clock time, IANA timezone, UTC offset, and daypart. The marker is reconstructed from the original browser message timestamp when the turn later appears in history, preserving prompt-prefix compatibility instead of injecting a new current timestamp into old turns.
3. Displayed message text is untouched.
4. LALM 2.1.29 strengthens the opening-social contract: no premature service-desk wrap-up such as “let me know if you need anything else today” on a conversation opener; one ordinary conversational follow-up is allowed.
5. LALM 2.1.29 treats the hidden user-local-time marker as authoritative temporal context and must not contradict its daypart/date/time relationship.

## Verification plan
- Confirm `/chat` loads `chat_user_time_context.js` before `chat_context_canonical.js`.
- Confirm live asset is served from the `runtime` branch.
- Confirm live LALM status reports 2.1.29 / `2.1.29-hot-social-temporal-v19`.
- Browser acceptance: fresh thread `Hey 👋` should produce an opening conversational response without a premature “anything else today” closure; camera log should show the new engine revision.
- Follow-up acceptance: ask a time-sensitive social question and verify wording is compatible with the browser-local daypart.

## Deployment boundary
Runtime-hot only. No production Vercel deployment or server restart is required or authorized for this release.
