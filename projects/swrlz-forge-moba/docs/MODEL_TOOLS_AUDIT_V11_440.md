## Reproduced defects and v11.440 corrections

1. **v436 hijacks native open-outline extrusion.** `se436_vr_cube_extrude.js` intercepts `extrude` for every `topologyMesh`, including a freshly VR-drawn open planar face. It routes to Manual Extrude, whose availability rejects open outer edges. The previous native outline extrusion accepted and thickened precisely that shape. The comment says preserve outline flow, but its type check includes it. Actual controller tracing and Thicken Outline reproduced the failure in v11.437. The v11.440 routing guard preserves native complete open outlines; real convex and concave outlines pass native positive/negative thickness, preview, one-step commit and exact Undo/Redo checks. A controller rerun also passes.
2. **VR Subdivide permits an invalid amount.** `model_vr_manual_workshop_v11_430.js` clamps every non-Inset/non-Extrude amount to .005, while `atelierAdaptiveRefineCandidate` requires maxEdge >= .025. VR can decrement to .005 and leave Preview enabled although the native operation rejects. Mobile already uses .025 minimum. v11.440 clamps this operation to .025, matching the native validator. The exposed minimum now produces a valid native refinement candidate.
3. **Mobile lesson can relabel an old pending preview.** The operation change listener resets amount/help without canceling a preview. The operation select is normally disabled during preview, but the real manual-workflow lesson button Make a rim calls `se430BeginnerNavigate('inset')` → `se430BeginnerSetOperation('inset',undefined)`, programmatically dispatching change even on that disabled select. An existing Extrude preview can now display Inset labels while Apply commits the old Extrude. The guide Extrude step happens to pass an amount, so its second amount-change event cancels; Inset does not. v11.440 cancels the owned preview before resetting the operation UI. The real guide route is included in mobile browser regression coverage.
4. **Accessory submenu prerequisite:** Body shape, Flap & details and Fit & attach were enabled before an accessory preview existed, although dispatch could not execute them. v11.440 disables those three cards until a preview is active and displays the prerequisite; the independent menu keeps ownership of controller rays. Native UI tests cover both states.
5. **Phone silhouette picking:** real Android-profile taps on visible vertices/edges at the outline could miss because the native picker required an exact triangle hit first. v11.440 allows at most eight nearby selected-mesh raycasts only for a touch miss in Vertex/Edge mode; existing distance/ordinal rules remain authoritative. Exact Face and mouse picking are unchanged. Seven real Three tests cover all four cube corners, a silhouette edge, bounded misses and unchanged mouse/face behavior; the actual mobile component/nudge/Undo workflow passes.
6. **Loaded motion picker:** imported keyed assembly data could be correct while the menu still listed the previous starter's Azure/Coral/Bunny components. The inspector now refreshes source-owned assembly controls when document, assembly or picker identity changes; unchanged pointer previews do not rebuild them. Actual loaded-project Play/Pause/Stop passes with source geometry and keys preserved.
7. **Current XR controller/menu matrices:** native tracking queries now apply their already-read current-frame pose to controller ray/grip nodes, and menu ray picking propagates current window matrices before render. No HMD pose, reference-space policy, additional pose query or XR loop was added. Real Three tests cover frame/reference coherence and a moved unrendered window.
8. **Invisible menu targets:** individual hidden cards are excluded from ray intersection. Visible disabled cards still own the pointer rather than selecting model geometry behind them.
9. **Visual feedback gap, not a source functionality failure:** `se350UpdateBrush` orients the visible brush ring toward the controller (`lookAt(controller position)`), not the actual surface normal. It does not encode strength in an inner ring. Online standard reference below motivates an optional aligned footprint/strength visualization; do not describe missing cosmetic parity as a broken brush.
