# §wyrl§ Engine v11.15 — native portrait and cloth surface study

The owner supplied the Scorchet festival turnaround and requested work in the existing Model Atelier. The new native 301-part scene is saved from the real editor after 80 inspector operations. It sweeps the paper bodies behind the face in profile while retaining the original attachment roots, and changes the fitted cloth, borders, coral wrap, jaw taper, portrait proportions, smiling lip contours, split dye crown, rear shoulder layering and ferret face details. The old v11.14 scene and every predecessor remain independent assets.

Reusable editor additions: a bounded jaw-taper control on portrait heads, a tapered-muzzle surface on spheres, a two-color crown surface, cloth-curvature and fold-depth controls on tailored panels, selected-part framing, and warm frontal fill for the assembly workspace. The surface values live in native part data, are validated before import, and participate in whole-model Undo/Redo and JSON/OBJ exports. Historical parts with no new fields retain their original geometry defaults.

The authoring job drives the existing select list, transform fields, spline path/radius editor and new surface fields through a real browser. It saves model JSON, reimports it, checks every authored value, and captures front, three-quarter, right, rear and detail views. The exported model is then packaged as the new starter; the operations are retained under authoring/ for review and repeatability. A local browser could not start because the workspace blocks its socket operation, so browser evidence comes from the repository's CI runner.

Acceptance still requires inspection of the returned views, all prior desktop/phone game and animation suites, new surface/geometry/undo/import checks, exact source reconstruction, merge, the final dedicated DEPLOY_REQUEST.json commit, terminal deployment and independent hosted source/asset verification. Human visual acceptance remains separate. No UV painting, production retopology or skeletal weighting is added.

Transform recipes use the inspector’s 0.001-unit precision. Model import normalizes missing pose collections to an empty list and null neutral pose; the authoring job verifies that normalization and saves a second native export. The actual exported scene, rather than the recipe’s predicted JSON, is the packaged source.

The expanded motion-key round trip exposed a preexisting validator mismatch: the importer emitted poseNeutral:null but rejected that value on the next import. The new append-only patch accepts an absent or null neutral pose and still rejects malformed actual frames. A generated-source CPU test covers repeated normalization and invalid-frame rejection, alongside the real browser model import test.
