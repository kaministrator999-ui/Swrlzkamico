# Restricted OVH engine starter deployment
The production root remains /var/www/swrlz-engine. No modification to §C, Nginx, auth, TLS, or other sites. The existing forced-command SSH gate is preserved as a legacy dispatcher. One administrator-side installation is required; repository access alone does not grant that privilege.

The publisher is installed root-owned under /usr/local/sbin; it only replaces existing Model Atelier scene/static model assets that match their recorded baseline hashes and SOURCE.json. No arbitrary commands, arbitrary paths, repo execution as root, or HTML/JS publishing. It stages a complete copy, atomically exchanges directories using Linux renameat2, checks file hashes, and keeps the previous full release for rollback. It refuses symlinks, writable/untrusted live files, changed baselines, mixed state, or missing receipt. The administrator should inspect the actual ownership and gate configuration if installation refuses. Existing §C commands are delegated unchanged.

First workflow stages the exact passed browser artifact in .deploy/engine-uv/payload (no live writes). After administrator install and successful stage, run the OVH §E restricted asset promotion workflow with operation=deploy or update PROMOTE.json on main. For rollback use operation=rollback. Check mode tests the gate only. GitHub verifies SSH host key, source revision, publisher receipt and that port 443 retains TLS/Basic Auth; authenticated browser live QA is a separate step. Grouped-layout experiment is excluded.
